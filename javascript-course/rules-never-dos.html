Rules & Never-Do’s

These are “best practice defaults” for your learning. They’re not laws, but they’ll keep your code clean.

Functions

  • Do: use return to give back a value.
  • Do: console.log() outside the function when you want to display results.
  • Never do: rely on console.log inside the function as the “output” (except debugging).
// Good
function add(a,b){ return a + b; }
const result = add(2,3);
console.log(result);

// Debugging is OK (temporary)
function addDbg(a,b){
  const sum = a + b;
  console.log("sum:", sum); // debug
  return sum;
}

If / Else

  • Do: use if (isLoggedIn) for booleans.
  • Do: use comparisons for numbers: age >= 18.
  • Never do: write if (age) when you mean if (age >= 18).
// Good
if (isLoggedIn) { ... }

if (age >= 18) { ... }

// Not best (truthy check, not a real age check)
if (age) { ... }

Equality

  • Do: use === and !== (strict) by default.
  • Never do: use == unless you *intend* type coercion.
// Good
if (value === 10) { ... }

// Risky (type coercion)
if (value == 10) { ... }

Arrays

  • Do: use push/pop and map/filter/find.
  • Do: use for..of for looping over items.
  • Never do: mutate arrays with splice unless you mean to change the original.
const nums = [1,2,3];

// Good
const doubled = nums.map(n => n * 2);

// Mutates original (use carefully)
nums.splice(1,1);

Loops

  • Do: use for when you need an index.
  • Do: use for..of for items.
  • Never do: create infinite loops accidentally (always make progress toward stopping).
// Index loop
for (let i = 0; i < arr.length; i++) { ... }

// Item loop
for (const item of arr) { ... }

Objects

  • Do: use dot notation for normal keys: user.name.
  • Do: use bracket notation when key is dynamic: user[key].
  • Never do: use brackets for everything when dot is simpler.
const user = { name: "Kevin", age: 45 };

user.name;        // best for normal keys

const key = "age";
user[key];        // required for dynamic keys
